Duel clock: design review and options

This reviews the two-player clock on branch claude/blissful-volta-vk87it next to main. The goal: the default game stays exactly as it is on main, and the shared clock becomes a separate, clean mode you only see once you choose it. Every mockup uses the real web/style.css, so it looks like the app.

What the review found

1
The settings hide in the About drawer. Name, room, minutes and Connect sit between the intro and the rules, so settings are mixed in with help text. Nothing on the game page says a duel exists, and the drawer gets longer for everyone who never uses it.
2
"Mode" means two things. The header pill is the helper mode (Normal, Basic, Advanced), and the code calls the clock a mode too (mode.press(), .mode-card). Give the clock a name that isn't "mode". These mockups use Duel clock.
3
Four times at once during a duel: the time since your last guess, the status line, two clocks, and the Game Timer by "Your guesses". The status line repeats what the clocks' names already say, so the mockups drop it and move the connection dot elsewhere. They keep the time since your last guess, since you kept it on purpose in be3be1d.
4
Whose turn it is is easy to miss. The running clock only gets a coloured border. Filling it in and adding "Your turn" or "Their turn" makes it readable from across the table.
5
Setting up takes too much typing. Both players have to invent the same room name and type it exactly, type a name, and type a number. The fix:
  • A room code made for you, plus a Share link (?room=…) that opens the other phone straight into the room.
  • Make the name optional. It defaults to "Player one" or "Player two".
  • Minutes as chips (3 · 5 · 10 · 15 · 30) instead of a number box.
6
Leave and changing the minutes are in the drawer too. Changing the minutes restarts both clocks, but you do it from a screen that hides the clocks. Keep the duel's controls next to the duel.
7
The code is already well separated. clock.js has its own state and storage and loads the library only on demand. The UI is the tangled part: the clock markup is in the drawer and app.js renders it. Put the duel's markup in one block that is hidden unless the duel is on, and have clock.js (or a small duel.js) draw it. Then app.js only calls press(), newGame() and init(), and the default page's markup matches main.

The options

Option A

A clock button in the header

One round button by New game opens a sheet from the top. The smallest change, but it squeezes the header ("Normal M…").

 Option B

Choose it in the menu, settings drop down from a bar

Your idea. "How you play" at the top of the drawer. A bar under the header holds the settings when open and the status when folded.

 Option C

A separate lobby screen

Make or join a room on its own screen, with a 4-letter code in tiles. The cleanest split, and the most to build.

 Option D

A chess clock pinned to the bottom

The clocks sit in a bottom dock, with the ticking side big and filled. Nothing above the keyboard moves.

Recommendation

Option B, plus the setup fixes from finding 5, which every option uses. It keeps the default game exactly as on main, it's the "dropdown at the top" you described, and it puts all of the duel in one place that folds away. If you'd rather the guess box never moves down, use B's way in with D's bottom dock for play. You can also mix them: C's 4-letter room code works in any option.

Other names than "Duel clock": Duel, Chess clock, Two phones, Versus. "Duel" is short enough for a pill and doesn't clash with the helper "modes".
